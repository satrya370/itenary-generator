## Deviations from the plan (with reasons)

1. **Inline execution.** The planned Haiku subagent was blocked by an auto-mode hook that changed its input; the work was done in the main session instead. The review stage must still be a separate run.
2. **Period words.** "pagi/siang/sore/malam" count as a clock marker only without minutes ("8 pagi"), not with minutes ("09:00 Pagi" is an activity named Pagi). Found by a test; plan wording left this open.
3. **Dictionary file** `import-headings.json` also holds the kind keywords and key-value labels (the plan named the file for headings only).
4. **Option synonyms** table exists but is empty (`optionSynonyms.entries: {}`); `matchOption` uses exact folded matches only. Synonyms are a later step, not invented here.
5. **Mode at source creation.** Plan step 3 said POST sources validates `mode` and returns it. Mode is chosen at the parse step instead (I2: mode is chosen before the import). Accepted in review R4.
6. **Release file count** rose from 41 to 51 (new config and import files are packaged). `validate:web-release` is valid. This is the only packaging change; no packager script was modified.

## Known gaps

- **Encrypted PDF:** no encrypted fixture was generated (no tool for it in the repo). The `IMPORT_ENCRYPTED` mapping exists in the worker (`PasswordException`) but is not exercised by a test. Covered by review only.
- **Worker termination:** the 1 ms deadline test proves `IMPORT_TIMEOUT`; it does not prove the worker thread is gone afterwards.
- **Headings** are id/en only (PD-2). Japanese, Chinese, French and Latin text imports as plain text and gives the AI step more work.
- **"title — place"** is not split (by design; CP031).
- **Duration key-value** ("Durasi: 6 jam") is left as unconsumed text.
- **Dry-run only.** The editor does not call the parse endpoint yet (CP032).
- **Scanned PDF detection** is a character-density heuristic (< 40 non-space characters per page); a text-layer PDF with very little text would be rejected too.
